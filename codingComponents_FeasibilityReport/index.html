Coding Components & Feasibility Report

Features

I plan to build out an air piano simulation using webcam hand tracking, an animated scroll survey with live survey response statistics, and a pre-recorded video demo as a fallback for users without webcams or who don't feel comfortable allowing camera access.

Technologies

I plan on using the MediaPipe Hands library for finger joint tracking and detection, which will use 21 hand landmarks per hand to determine whether a user's fingers are raised or curled. I'll use the Tone.js library for generating piano sounds triggered by finger movement. Additionally, I'll use either the Canvas API or p5.js for rendering the hand skeleton overlay. I'll probably use Firebase or Supabase for storing and retrieving live survey response data. Lastly, I'll be using HTML, CSS, and JavaScript for the scroll-based survey with fade-in animations.

Skill Assessment

I'm comfortable with HTML, CSS, and JavaScript. Canvas API, p5.js, MediaPipe, and Tone.js are all new to me, but each library has accessible documentation with live demos and code samples that I can reference while building. Firebase/Supabase are also new, but I only need basic read/write functionality for storing survey responses, which seems to be covered well in their getting started guides. I'm feeling confident that I can learn everything I need within the project timeline.

Difficulties

I think that the biggest challenge will be developing the finger detection logic. MediaPipe provides 21 joint coordinates per hand, but determining whether a finger is raised or curled requires custom threshold logic that could vary across hand sizes and camera angles. If hand tracking ends up being too unreliable, I might need to simplify to fewer fingers or add a click/tap fallback alongside the tracking. I'll also need to carefully adjust Tone.js so that the sounds getting triggered will sound clean without overlapping with one another.
